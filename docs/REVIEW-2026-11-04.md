# Review: November 4, 2026

Scope: HEAD d6ad411 (including ff98e86's swipe/theme changes), the staged sharing/UI patch,
and Android/web behavior in the affected flows. New review edits are unstaged; the original
28-file staged patch was preserved. No commit or deployment was made.

## Fixed findings

- **P2: whole-ayah swipe regression on web.** The staged half-width threshold also affected
  whole-ayah navigation, making an ordinary short swipe do nothing on a wide screen. Restored
  a short threshold matching Android's 56 dp gesture, while keeping halfway snapping for words.
  Vertical scrolling, returning drags and cancelled touches no longer masquerade as taps.
- **P2: web word gesture lifecycle.** Overlay playback-follow could change the word under the
  finger; returning to the start could trigger tap-to-advance; lost capture had no cleanup.
  Playback-follow now yields to the drag, movement is remembered, and cancellation restores the
  centered position. Disabled swipes and vertical movement do not become taps.
- **P2: scene palette leaked beyond the player.** Inline sidebar/tab-bar colors survived navigation.
  Clear them on teardown and invalidate asynchronous background results after leaving the player.
- **P2: Android text-share failures escaped the UI coroutine.** Added busy/error handling,
  cancellation propagation and stable option snapshots. Both platforms reject unavailable selected
  text instead of silently sharing only a reference. The Android share dialog scrolls on small screens.
- **P2: range text sharing required a video export.** Moved it outside the completed-export state
  on both platforms and added explicit Copy text actions alongside Share text. Arabic-only web
  sharing no longer depends on downloading unrelated word-translation data.
- **P2: web-server SQLite handles were not explicitly closed.** Close each request thread's handle
  and the initial setup handle. The test's own direct connection is also closed during teardown;
  the Windows server suite now completes without a database-lock cleanup failure.
- Improved the web end-card QR rendering with integer-sized modules and a four-module white border.
  Windows browser tests can use `python` or the `PYTHON` override; image-download testing explicitly
  selects the download fallback instead of waiting on Chrome's native share sheet.

## Design and release recommendation

Separate video/image sharing from text sharing. Keep Bismillah and A'udhu independent; preserve
Al-Fatihah 1 and At-Tawbah guards. The staged optional closing card already supplies the app name,
Play Store URL and QR code. A rendered URL is not a clickable video link; the QR is the useful action.

**Hold production deployment pending the device checklist in [TODO.md](TODO.md).** In particular,
verify slow Android swipes during playback and at playlist boundaries, real MP4 audio/video alignment,
and QR scanning after compression. Review export attribution requirements now that automatic source
captions are removed. The review did not verify the live Play Store listing or scan an exported QR.

One pre-existing parity difference remains documented: the web settings expose optional seeking
inside whole-ayah audio from the word overlay, while Android retains the stored preference but does
not expose or apply it in that overlay. Decide whether to restore that optional feature on Android
or retire it consistently; ordinary WORD_BY_WORD playback is a separate path.

Translations, additional reciters and tafsir are recorded as a separate implementation roadmap in
[TODO.md](TODO.md). Use provider catalogs and downloadable resources with explicit capabilities,
rather than bundling an unverified "all reciters" list into this UI-fix release. Current repository
rules require validated timing data matching each reciter's exact recording.
